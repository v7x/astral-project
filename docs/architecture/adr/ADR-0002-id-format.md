# ADR-0002: ID format

## Problem

Trusted records need typed, unambiguous identifiers before persistence and protocol work.

## Choices

- Canonical UUID4 values generated by Python standard library.
- Custom sortable identifier or UUIDv7 implementation.

## Chosen choice

Use lower-case canonical UUID4 strings. Each semantic ID has its own immutable Python type. Request numbers are positive integers.

## Security effect

UUID4 obtains randomness from OS CSPRNG. Canonical parsing rejects confusing alternate spellings and wrong UUID versions. Distinct Python types prevent accidental interchange in typed code.

## Rejected choices

- Custom sortable IDs: extra implementation and review surface before ordering is needed.
- UUIDv7: Python 3.12 lacks standard implementation; custom timestamp/random bit handling is unnecessary now.

## Tests

- invalid, noncanonical, and non-v4 identifiers reject;
- generated IDs parse into same semantic type;
- request number rejects zero, negative, and boolean values.

## Reconsideration trigger

Persistent ordering or database locality requires sortable IDs and a reviewed standard UUIDv7 implementation is available.
